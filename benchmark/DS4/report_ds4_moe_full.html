4. Considerations: expansion configuration

  • N=12 (2× native top-6) is an aggressive first test. The measured routed experts/token was 9.71 (adaptive range 3-12 under T=0.8) vs 6 native. A softer first step (N=9, i.e. 1.5×) halves the added-expert weight and is the natural next experiment.
  • Threshold T=0.8 keeps experts while their sqrt-softplus score stays above 0.8 × score(rank N/2), with a floor of N/4=3. Ranks 7-12 enter with linear decay 0.99→0.50. A stronger decay (--moe-expert-decay-end 0.3) would fade the extras harder; a narrower layer window (--moe-expert-layer-start 0.75) would localize the change further.
  • Layer scope 30-42 of 43 was chosen to mirror the late-layer scoping used on Qwen. The first hash-routed layers of DeepSeek-V4 never route through the expansion by design.
  • The clean-subset net is negative uniformly across all three subjects (each subject individually slightly negative): the effect looks systemic (routing-scale semantics or quantization noise) rather than domain-specific. See sections 5-6 for the two main hypotheses.
  • Statistical caveat: net -4 over 10 divergent questions (≈1.3σ) is not significant by itself; but it is consistent in direction across the raw view, the clean view, and the per-subject breakdown, which strengthens the conclusion that this configuration does not help this model/quant combination.

5. Considerations: quantization (UD-IQ2_M)

  • At ~2-bit average, both the expert weights and the router projection (ffn_gate_inp) are quantized. Router logits therefore carry quantization noise of the same order as the score gaps between ranks 6-12 - precisely the ranks the expansion adds.
  • The native top-6 is robust to this noise (deep biases + strong scores), but ranks 7-12 have noisy sqrt-softplus scores: the expansion can amplify experts that are quantization-noise rather than signal. This matches the per-subject pattern: a small uniform penalty everywhere instead of a domain-specific effect.
  • At higher precision (Q4_K_XL / Q6-style) the marginal experts beyond the native top-6 carry more usable signal: the same experiment on a higher-quant build (needs a larger host) is the cleanest way to separate "expansion hurts DS4" from "expansion hurts 2-bit DS4". The Qwen3.6 result (+2.02 points at Q6_K) suggests quantization precision is a real moderator of the expansion benefit.

6. Considerations: expert weight-sum semantics for sqrt-softplus + bias

How this model's router weights work. DeepSeek-V4-Flash routes with sqrt-softplus gating: scores = sqrt(softplus(logits + expert_bias)). These are positive but unbounded scores, not probabilities: the sum over the selected experts (S = Σ scores) is token-dependent and typically well above 1. In llama.cpp the handling is controlled by two GGUF metadata keys:

  • expert_weights_norm (llama.cpp default false): when false, the MoE output uses the raw sqrt-softplus scores as weights - the routed-branch magnitude is Σ scores × expert_weights_scale;
  • expert_weights_scale (llama.cpp default 0.0; DeepSeek family typically uses a routed-scaling factor such as 2.5): applied after normalization when norm is on, after gathering when off.

The deviation introduced by the expansion. The current expansion post-pass (build_moe_expansion_weights) always renormalizes the kept weights to sum 1 (following the Qwen3.6 spec, where the stock router is a softmax and already sums to 1 - there the renormalization is a no-op semantically). For DeepSeek-V4 with expert_weights_norm=false, this replaces the raw-score sum with exactly 1: the routed-branch output magnitude changes by Σ scores (≈ 1.5-4× smaller), perturbing the residual stream of every expanded layer. That is a plausible contributor to the observed regression, independent of the routing choice itself.

The ds4 precedent. The original ds4 implementation for DeepSeek-V4 Flash does not renormalize: kept experts keep their raw router scores and the dropped mass is simply discarded (only the Qwen3.6 path renormalizes). Our port currently renormalizes for every model.

Proposed fix (implementation work). Add a renormalization mode to build_moe_expansion_weights: renorm = auto | always | never where auto follows the stock behavior of the model (expert_weights_norm true → renormalize; false → cut + decay without renormalization). Then rerun N=12/T=0.8/L30-42 with renorm=never: if the regression is scale-driven, several points should recover; if it persists, the negative verdict is genuinely about adding experts to this model/quant.

How to check which case your GGUF is in: ./llama-gguf --dump model.gguf | grep -i weights_norm (or inspect with gguf-dump). If the key is absent, the llama.cpp default (false) applies.

7. Suggested next experiments (one variable at a time, paired)

  1. renorm=never rerun of N=12/T=0.8/L30-42 (isolates the weight-sum semantics; requires the small code change above).
  2. N=9, T=0.8 (1.5× instead of 2×): softer expansion on a 2-bit router.
  3. N=12, decay-end 0.30: same budget, harder fade of the extra ranks.
  4. Higher-quant rerun (UD-Q4_K_XL on a larger host): isolates the quantization moderator.
  5. Keep the native top-6 run as the fixed reference for every paired comparison.

Methodology

  • Paired protocol: same 198 GPQA-diamond questions, temperature 0 (greedy), identical prompt and generation config in both runs; both runs executed sequentially on the same host.
  • Accuracy = evalscope review outcome (ANSWER: [LETTER] extraction vs target).
  • Truncated answers (stop=length at the ~16.3k server context) are scored as-is by evalscope (near-zero, no final ANSWER line); section 2 removes them from both sides to measure routing quality on completable questions only.
  • Subject assigned by matching each question text against the original GPQA dataset (Subdomain / High-level domain): 198/198 matched.
  • Quantization caveat: UD-IQ2_M is a ~2-bit quant; both runs share it, but its interaction with expansion is discussed in section 5.
